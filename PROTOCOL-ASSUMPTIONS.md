# Native Codex App-Server Protocol Assumptions

**Status:** V2.1.3 maintenance baseline, derived from the accepted Bridge implementation and the established stable upstream contracts used for this maintenance round. Revalidate this checklist whenever the native Codex runtime is upgraded. This is an upgrade aid, not a complete app-server protocol reference.

LCB remains a thin supervisory MCP adapter. The native Codex thread/session is the sole execution source of truth; Bridge state must not become a second task system, model-state registry, or lifecycle authority.

## Assumption checklist

| Assumption | Type | Code & tests | Current status | If wrong, recheck |
| --- | --- | --- | --- | --- |
| `model/list` accepts `limit`, opaque `cursor`, and `includeHidden`, and returns `data` plus `nextCursor`. Picker discovery defaults to visible models. Entries may contain `id`, `model`, `displayName`, `hidden`, `defaultReasoningEffort`, `supportedReasoningEfforts`, `upgrade`, `inputModalities`, `supportsPersonality`, and `isDefault`; extra fields may appear. | Upstream contract | `src/tools.ts`: `modelListPage`, `sanitizedModelEntry`, `#models`; `test/tools.test.ts`: bounded-page/future-field case | Upstream contract baseline; Bridge projection verified by current tests | Recheck request names, cursor termination, required envelope fields, entry identifier fields, visibility semantics, and sanitizer budgets. |
| `codex_models` is one bounded, sanitized page marked `codex_app_server_model_list`; it is discovery only and creates no cache. Explicit overrides instead read a fresh hidden-inclusive full catalog with page, entry, and cursor-cycle bounds. | Bridge policy | `src/tools.ts`: `#models`, `#fullModelCatalog`, `#validateExecutionOverrides`; `test/tools.test.ts`: hidden-model pagination and cursor-cycle cases | Verified by current tests | Recheck bounds and failure behavior; do not replace fresh discovery with a persistent catalog or current-model registry. |
| Explicit `model` and/or `effort` on `turn/start` become native defaults for later turns on that thread. Omitting them preserves native state, so an ordinary continuation sends neither and must not call `model/list`. | Upstream contract + Bridge policy | `src/tools.ts`: `#turn`, `#validateExecutionOverrides`; `test/tools.test.ts`: ordinary-continuation and exact-token cases | Upstream contract baseline; omission and pass-through verified by current tests | Recheck native persistence and omission semantics before changing payload construction. Never emulate native defaults in Bridge state. |
| Override validation is deliberately asymmetric: unknown model-only overrides fail locally; model+effort fails only when all matching entries advertise support and prove incompatibility; missing or unusable support metadata defers to native Codex; effort-only requires catalog-wide advertised token existence and never infers the current model. | Bridge defensive policy | `src/tools.ts`: `modelIdentifiers`, `advertisedReasoningEfforts`, `#validateExecutionOverrides`; `test/tools.test.ts`: unknown-model, model+effort, absent-metadata, and effort-only cases | Verified by current tests | Recheck identifier aliases and `supportedReasoningEfforts` shape. Preserve native authority when compatibility is unknowable. |
| Stable `thread/read` is not assumed to expose a reliable current model. Persisted history may restore bounded observation context, but not model state. | Upstream limitation + Bridge policy | `src/tools.ts`: `#observe`, `#validateExecutionOverrides`; `test/tools.test.ts`: effort-only validation without model inference | Upstream contract baseline; no-reconstruction behavior verified by current tests | If upstream adds a stable current-model field, first decide whether reading it on demand is sufficient; do not introduce a registry by default. |
| `item/permissions/requestApproval` is answered with exactly `{ permissions, scope? }`. `permissions` is the granted subset and `{}` is valid. `scope: "session"` persists for the session; `scope: "turn"` or omission is turn-scoped. Malformed or mixed response shapes fail before the request is claimed. | Upstream contract + Bridge defensive policy | `src/tools.ts`: `SUPPORTED_RESPOND_METHODS`, `#respond`; `test/app-server.test.ts`: exact/empty permission responses and pre-claim rejection cases | Upstream contract baseline; Bridge construction and fail-closed validation verified by current tests | Recheck the exact result object, scope tokens/default, and claim ordering before accepting any new permission fields. |
| Server-request identity is the original typed string-or-integer JSON-RPC id plus exact method/thread/turn scope. Concurrent duplicate typed ids are protocol errors. A failed response write releases the claim and restores the same pending request. | Upstream identity assumption + Bridge defensive policy | `src/runtime.ts`: `PendingServerRequest`, `recordServerRequest`, `claimPending`, `releasePending`, `completePending`; `src/app-server.ts`: `rpcKey`, `respond`, `#dispatch`; `test/app-server.test.ts`: failed-write and duplicate-id cases | Verified by current tests | Recheck id types, uniqueness lifetime, scope fields, and write acknowledgement semantics. Never synthesize ids or relax scope matching. |
| `mcpServer/elicitation/request` has no supported response contract in Bridge. It remains pending and observable instead of being silently or generically answered. | Bridge policy | `src/tools.ts`: `SUPPORTED_RESPOND_METHODS`, `#respond`; `src/runtime.ts`: `recordServerRequest`; `test/app-server.test.ts`: unsupported-elicitation case | Verified by current tests | Add support only from a stable upstream response contract, with explicit schema, scope, and regression coverage. |
| Acknowledgement timeout for already-written `thread/start`, `thread/resume`, `turn/start`, `turn/steer`, or `turn/interrupt` means **UNKNOWN / possibly accepted**. Bridge must not auto-retry; the supervisor must observe or read native state before deciding whether any retry is safe. | Upstream uncertainty + Bridge safety policy | `src/app-server.ts`: `MUTATING_REQUEST_METHODS`, `requestTimeoutError`, `#request`; `test/app-server.test.ts`: mutating-timeout cases | Verified by current tests | Recheck acknowledgement timing and idempotency only if upstream guarantees change. Keep timeout distinct from confirmed rejection. |
| App-server responses are extensible. Bridge validates required envelopes/fields where needed, then applies bounded sanitization/projection; model entries are not closed-world rejected merely for future fields. | Upstream extensibility assumption + Bridge defensive policy | `src/tools.ts`: `responseRecord`, `modelListPage`, `sanitizedModelEntry`, `#models`; `test/tools.test.ts`: malformed bounds and preserved future-field case | Verified by current tests | Recheck required-field validation and transport bounds when upstream adds nesting, larger values, or new identifier/support shapes. |
| Runtime app-server `clientInfo.version` and MCP `serverInfo.version` share the code constant `VERSION`. Package, documentation, and platform release anchors are separate consistency checks, not app-server protocol assumptions. | Bridge-local consistency | `src/version.ts`: `VERSION`; `src/app-server.ts`: initialize `clientInfo`; `src/mcp.ts`: initialize `serverInfo`; `test/version.test.ts`: release-anchor guard | Verified by current tests | On a release bump, update the canonical constant and every guarded external anchor together; keep upstream compatibility conclusions separate. |

## Revalidation triggers

Revisit this checklist when:

- the official Codex executable or app-server protocol is upgraded;
- any listed method changes request, response, pagination, id, scope, or timeout semantics;
- a required-envelope or protocol-identity check begins failing against native Codex;
- the related model, response, timeout, duplicate-id, or version-anchor tests change or fail;
- Bridge proposes support for a currently deliberate non-assumption.

## Deliberate non-assumptions

- No `serviceTier` or provider-capability abstraction.
- No current-model registry, model cache, or model-state reconstruction from `thread/read`.
- No dependency on `command/exec`, `thread/turns/list`, or `sourceKinds`.
- No elicitation response support.
- No queued-message facade; `turn/steer` remains a semantic correction to one active turn.
- No new late-response telemetry contract or public surface was added by the V2.1.3 maintenance round.
