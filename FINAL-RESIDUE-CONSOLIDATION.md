# Final residue consolidation

Baseline: `dfba0132723fab4d178782899b73fe626f13055e` on `main` and `origin/main` before this closure. The canonical checkout had `lcb-n1-native-surface` at `cb4a569a4bdb80c786d1c997f540a5437f3334a0` plus uncommitted code, tests, documents, and two generated duplicate-request logs. This ledger records the disposition of those changes and every discovered LCB donor ref/worktree. `ABSORB` means the capability was missing from baseline; existing baseline capabilities are recorded as already absorbed and the duplicate donor is abandoned.

| Source | Capability or residue | Decision | Reason |
| --- | --- | --- | --- |
| `dsh-w4-g2-lcb-socket-shutdown` dirty tree | Close an inherited Unix socket service while an MCP client remains connected | **ABSORB** | Baseline awaited `Server.close()` before destroying live sockets, which can hang shutdown. The transport fix destroys sessions before awaiting listener close and has a live-socket regression test. |
| `lcb-n1-native-surface` dirty tree | Mark semantic progress as derived, non-authoritative diagnostic data | **ABSORB** | The existing projection remains useful, but callers must not mistake it for native lifecycle or control authority. |
| `lcb-n1-native-surface` dirty tree | Structured UserInput, output schema, turn trigger, fork/compact, direct native option handling | **ABANDON duplicate** | Baseline already has these through `codex_turn`, `codex_turn_start`, `codex_thread_lifecycle`, and native allowlists; the WIP would narrow or replace the thicker surface. |
| `lcb-n1-native-surface` dirty tree | App-server child auto-recovery/backoff and synthetic degraded state | **ABANDON** | Recreates recovery orchestration and can obscure an unknown mutating outcome. The baseline deliberately latches child death. |
| `lcb-n1-native-surface`, `hop-m2b1-runtime-authority` | Bridge runtime/authority identity metadata | **ABANDON** | Local process identity is not a Codex-native capability or a reliable authority claim. Service identity is available from systemd and the exact socket. |
| `td-e2e-1-r2`, `swdt-p1a-minimal-native-binding`, `swdt-p1a-live-evidence` | Exact native thread start and turn start; delivery action request handling | **ABANDON duplicate** | Baseline already contains direct native start tools and pending request handling. Donor delivery/reviewer boundaries and PREBOUND workflow belong outside this consolidation. |
| `bootstrap-repair-lcb` dirty tree | Version 2.1.4 and read-only Lead/Reviewer delivery policy rewrite | **ABANDON** | Version bump and Host workflow policy are unrelated to native capability exposure; baseline supersedes the donor code. |
| `lcb-native-agent-policy-opus-final` and `lcb-native-agent-policy-opus-review` dirty trees | Fixed lead/child model policy, managed hooks, local bindings/audit | **ABANDON** | Rebuilds authority, permissions, and policy state in the Bridge. Codex native config and the caller own model/agent choices. |
| `lcb-thick-consolidation` | Earlier thick candidate | **ABANDON duplicate** | It points to baseline `main`; the useful native read/action allowlists, history, structured turn, rate limits, Goal, and pending-request surfaces are already present. |
| `swdt-p1a-live-evidence` state worktree | Pilot evidence and PREBOUND documentation | **ABANDON** | Historical cutover evidence; no missing adapter capability. |
| `wsl-linux-enable` / `origin/wsl-linux-enable` | Linux enablement and native rate-limit read | **ABANDON duplicate** | It is an ancestor of baseline and its useful capability is already merged. |
| Stale `/tmp` worktree registrations and generated duplicate-request logs | Obsolete checkout/test artifacts | **ABANDON** | No source capability. |

The current `main` already exposes bounded stable and experimental Codex app-server operations, including thread history, lifecycle actions, native review, settings, and direct input variants. This closure adds no Host continuation, watchdog, reroute, retry, reviewer handoff, task queue, memory orchestration, or extra permission layer. The old TencentDB/MemoryCore code already in baseline was neither used nor expanded here; production automatic recall and writeback remain disabled by the existing service environment.
